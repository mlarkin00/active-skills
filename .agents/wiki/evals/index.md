# Pitfall

* [A trigger probe scores every positive as a miss for a skill that is also installed](run-eval-scores-an-installed-skill-as-a-miss.md) - Injecting a uniquely-named command file and counting only calls to that name reads 0.00 for descriptions that are in fact firing, because the installed plugin skill wins the call; fixed 2026-08-06 by adding a live mode and by counting contaminated runs as unmeasured rather than failed.
* [An SDK-based propose step cannot run on an OAuth-authenticated machine](run-loop-needs-an-api-key-this-box-does-not-have.md) - Calling the Anthropic API directly needs ANTHROPIC_API_KEY, which a machine authenticating Claude Code through OAuth does not have; resolved 2026-08-06 by shelling out to claude -p, the same transport the eval half uses.
* [Killing an eval runner leaves its nested claude -p sessions running and billing](nested-sessions-outlive-a-killed-parent.md) - Pool workers are separate processes that survive the parent, so the finally blocks that terminate nested sessions never execute and up to --num-workers sessions keep running invisibly after the run is aborted.
* [Parallel trigger probes sharing one project root steal each other's command files](parallel-probes-collide-in-a-shared-project-root.md) - Concurrent probe runs writing into the same .claude/commands/ each see every other run's probe, and a session that invokes a sibling's probe carries a different UUID so it is scored as a miss — undercounting worse the more workers run.

# Runtime Behaviour

* [claude -p --output-format json returns an array of messages, not a result object](claude-p-json-output-is-an-array.md) - The text lives on `result` of the last message whose type is `result`, alongside is_error and total_cost_usd; and stdin must be redirected or every call stalls three seconds waiting for input.
* [OpenCode sessions store no queryable injected-context epoch, unlike Claude Code's attachment records](opencode-sessions-store-no-queryable-context-epoch.md) - OpenCode persists the conversation (message/part tables) but not a session_context_epoch — that table is empty across every session in the DB, so a show-context-style reader cannot enumerate injected instruction files, hooks, or skill/MCP listings from ground truth the way the Claude Code backend can.
* [Passing enabledPlugins via --settings hides a plugin from one claude -p run](settings-json-isolates-a-plugin-per-invocation.md) - A JSON string given to --settings merges over the user's settings for that process only, so setting enabledPlugins.<plugin@marketplace> to false removes the plugin's skills from a nested run without touching the user's environment.
* [Trigger evals at 3 runs per query cannot separate two skill descriptions](three-runs-per-query-cannot-separate-two-descriptions.md) - Two candidate descriptions produced an identical mean positive trigger rate of 0.500 while 4 of 10 individual queries flipped by 0.66 or more, so the per-query pass/fail totals that skill-creator-enhanced reports are noise.
